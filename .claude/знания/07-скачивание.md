# Как достать запись стрима

Основной путь — `python скачать.py "<ссылка>"`. Здесь то, что стоит знать,
когда он не справился.

## Twitch — берётся штатно

```
python скачать.py "https://www.twitch.tv/videos/<id>"
```

Мастер-качество, без фокусов. Замер: 46.7 минуты в 1080p60 — 3.04 ГБ,
скачалось за ~2 минуты.

## Kick — ссылка из браузера СЛОМАНА, и это лечится

Адрес вида `kick.com/КАНАЛ/videos/<uuid>` содержит id нового формата
(UUIDv7, начинается на `01…`). yt-dlp берёт id прямо из адреса и стучится
в API, который знает только старый формат, — получает 404 и сваливается
в generic-экстрактор.

**Обход, который делает `скачать.py` сам:**

1. `GET https://kick.com/api/v2/channels/<канал>/videos` — список последних
   трансляций. (v1 у многих каналов уже 404.)
2. Найти нужную запись по названию и дате.
3. Взять из неё **`video.uuid`** — это старый формат.
4. Скормить yt-dlp адрес прежней формы, но с этим uuid.

Посмотреть список трансляций канала:

```
python скачать.py "https://kick.com/КАНАЛ" --список
```

**Про живой стрим.** В том же ответе есть `is_live` и `duration`.
Пока стрим идёт, `is_live: true`, `duration: 0`, плейлист растёт — скачается
только записанное на данный момент, то есть огрызок. Скрипт об этом
предупреждает. Дождаться конца стрима: тогда `duration` станет реальным.

Форматы Kick: 160p / 360p / 480p / 720p60 / 1080p60.
1 ч 42 мин в 1080p60 = 6.7 ГБ.

## YouTube

Работает штатно. Скрипт сам подбирает формат `bv*+ba`.

## TikTok — по ссылке на ролик не качается

Проверено пятью запусками подряд: `Unable to extract universal data for
rehydration`. Повтор не помогает, обновление yt-dlp на момент проверки
тоже. Нужен конкретный чужой ролик для разбора — проще скачать вручную
и положить файл в `СТРИМЫ/`.

**Состояние может измениться:** экстракторы ломаются и чинятся постоянно.
Первое, что стоит попробовать при любой ошибке, — обновить `yt-dlp` в окружении проекта (см. «Окружение» в `CLAUDE.md`).

## Телеграм и всё остальное

Скачать вручную и положить файл в `СТРИМЫ/`. Проверить, что доехало:

```
python скачать.py "СТРИМЫ/файл.mp4"
```

Покажет разрешение, длительность, вес.

## Файл ещё качается

Признак — `moov atom not found` у ffprobe и растущий размер файла.
Не запускать конвейер: он прочитает огрызок и не скажет об этом внятно.

Правильно: дождаться, пока размер перестанет расти **И** ffprobe начнёт
читать файл. Только потом `scan`.

## Стрим приходит частями

Записи на 2–8 часов часто лежат несколькими файлами по 90 минут.
Это ОДИН стрим, разрезанный на куски: нумерация подряд, содержимое
продолжается. Гонять конвейер надо по каждому файлу, а искать моменты —
помня, что разговор может начаться в конце одного файла и кончиться
в начале следующего.

## Ловушка кэша при совпадении имён

У каждого стрима свой кэш: `движок/work/<имя файла>/`.
Если новый файл называется как разобранный раньше, движок заводит отдельную
папку и предупреждает — в кэше лежит штамп с размером исходника.

**Признак подмены на глаз:** длина стрима в выводе `scan` не совпадает
с реальной. Один раз это стоило целой партии: моменты выбирались
по расшифровке прошлого стрима, а резались из нового.

## Скорость и очередь

По умолчанию скорость не ограничена. После каждой присланной ссылки Claude
предлагает пользователю задать лимит на текущую сессию и передаёт его флагом
`--скорость` (15 Мбит/с ≈ `--скорость 1.8M`). Несколько ссылок качаются
последовательно, по одной. Порядок — `.claude/commands/скачать.md`.

Замер 2026-11-24: Twitch отдаёт одну запись примерно на 9–10 Мбит/с,
параллельная закачка двух записей суммарно быстрее не была.

**VPN.** Если в системе включён VPN (адаптер tun2socks) и он отвалился, yt-dlp
сыплет `SSL: UNEXPECTED_EOF_WHILE_READING`, а после 20 попыток пропускает
фрагменты. Закачку остановить, попросить пользователя переподключить VPN,
затем перезапустить ту же команду: она продолжит с места остановки.
