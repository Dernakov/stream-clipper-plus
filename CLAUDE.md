# Нарезка стримов на вертикальные клипы

> **Новая сессия? Начни с `/начинаем`.** Команда сама поймёт, первый это
> запуск или продолжение работы, проверит окружение и поднимет контекст.
>
> Если пользователь написал просто «начинаем», «поехали» или «продолжаем»
> без слэша — это то же самое. Запускай `/начинаем`, не переспрашивай.

## Что это за проект

Рабочая папка с тремя шаблонами. Каждый — своя команда:

| Команда | Что на входе | Что на выходе |
|---|---|---|
| `/мем` | ссылка Twitch на стрим целиком (2–8 ч) или файл в `СТРИМЫ/` | вертикальные мемы 1080×1920 для TikTok |
| `/файт` | файлы в `СЫРЫЕ КЛИПЫ/` или ссылка на клип Twitch | вертикальные файты 1080×1920 для TikTok |
| `/матч` | ссылка Twitch на запись одной игры или файл в `СЫРЫЕ МАТЧИ/` | горизонтальный ролик 16:9 для YouTube |

Английские `/mem`, `/fight`, `/match` и старые `/нарезка`, `/клипы` — те же
команды. На выходе — папка в `Clips Ready/` с готовыми роликами.

**Три команды можно вести одновременно в трёх разных чатах.** Движок это
выдерживает: у каждого процесса свои временные файлы, раскладка привязана
к записи, у каждой задачи своя папка результата. Правила для чата — раздел
«Параллельная работа» ниже.

Работает локально: `ffmpeg` + распознавание речи на процессоре.
Ни GPU, ни платных API не нужно.

## Разделение труда — это главное

| Кто | Что делает |
|---|---|
| **Скрипт** | находит кандидатов по громкости, речи и движению; режет, собирает, рендерит |
| **Ты (Claude)** | читаешь расшифровку, СМОТРИШЬ КАДРЫ, выбираешь моменты и пишешь заголовки |
| **Пользователь** | даёт запись стрима и получает готовые ролики, которые передаёт стримеру. Отсмотр и публикация — на стримере, ничего никуда не загружаем |

Механика — 5 секунд работы скрипта. Вся ценность в выборе момента
и в заголовке. Формула не понимает смысла: она пропускает езду на машине
и послематчевые таблицы, а тихую бытовую сценку — лучший материал — не видит
вовсе.

## Правила работы

- **Отвечай на языке пользователя.** По умолчанию русский.
- **Пользователю нужен только готовый ролик.** Разбираться в процессе он не
  хочет: команды запускай сам, не объясняй, что и как делаешь, не показывай
  вывод скриптов. В ответе — готовые файлы и описания к ним. Об ошибке пиши
  только если она мешает получить результат и нужно его решение: одной фразой,
  без технических подробностей.
- **Не выдумывай про алгоритмы TikTok.** Проверенных фактов мало, форумного
  фольклора много. Не уверен — так и пиши: «уверенность низкая».
- **Не натягивай количество.** С одного стрима 5 клипов, с другого 1 — это
  нормальный итог. Лучше меньше и сильнее.
- **Кадры важнее расшифровки.** Ни транскрипт, ни формула не видят инвентарь,
  карту, экран смерти и переключение сцены. Смотри кадры глазами до того,
  как писать заголовки.
- **Никаких паролей и ключей в файлах.** Их здесь и не нужно.
- **Архив и удаление записи — только после приёмки.** Пользователь пересматривает
  все ролики и явно говорит, что всё принято. Тогда запустить `движок/приёмка.py`.
  Порядок описан в `.claude/знания/09-результат.md`.

## Окружение

- Везде, где в документах проекта написано `python`, использовать Python
  из окружения проекта `.venv` (Python 3.13: на 3.15 нет сборки
  `onnxruntime`). Windows — `.venv\Scripts\python.exe`, macOS/Linux —
  `.venv/bin/python`. Вместо `pip` — `python -m pip` того же окружения.
- `ffmpeg` и `ffprobe` должны быть в PATH. Если их там нет, путь к папке
  с ними задаётся переменной окружения `FFMPEG_DIR`: движок добавит её
  в PATH сам.
- Скрипты движка сами переносят временные файлы и кэши в `.cache/` проекта
  через модуль `движок/пути.py`. Новый скрипт должен импортировать его первым.

## Параллельная работа

В соседних чатах одновременно могут идти `/мем`, `/файт` и `/матч`.

- **Этап для строки состояния здесь пишется в `.cache/этап-<команда>.txt`**
  (`этап-мем.txt`, `этап-файт.txt`, `этап-матч.txt`), а не в общий `этап.txt`
  из глобальных правил. Строка состояния показывает все сразу. В конце — `Готово`.
- Разовые файлы чата — в `.cache/<команда>/`, не в корень `.cache/`.
- Каждая задача работает только со своей папкой исходников и своей папкой
  в `Clips Ready/`. Чужие не трогать.
- Числа раскладки конкретной записи — в `движок/work/<запись>/layout.json`
  (`раскладка.py … --принять`), **не** в `мои_настройки.py`: его читают все.
- Имя папки результата брать один раз: `clipper.py batchname … --kind <Тип>`,
  и передавать в каждый `cut` через `--batch`.
- В журнал и память — только дописывать в конец.
- Новый код движка: временные файлы — только в `clipper.job_dir()`, никаких
  постоянных имён вроде `work/tmp.wav`; готовый файл класть на место через
  `clipper.finish_file()`.

## Карта файлов

| Где | Что |
|---|---|
| `CLAUDE.md` | этот файл — правила и точка входа |
| `.claude/знания/` | **база знаний**: как выбирать моменты, писать заголовки, не терять охват |
| `.claude/commands/` | команды: `/начинаем`, `/мем`, `/файт`, `/матч`, `/скачать`, `/раскладка`, `/запомнить`, `/статус` (плюс синонимы `/mem`, `/fight`, `/match`, `/нарезка`, `/клипы`) |
| `.claude/память/` | что накопилось по ходу работы: предпочтения, журнал клипов, статистика |
| `движок/` | весь код. Пользователю сюда заходить не нужно |
| `движок/мои_настройки.py` | личные настройки; переживает обновление шаблона |
| `СТРИМЫ/` | стримы целиком для `/мем` |
| `СЫРЫЕ КЛИПЫ/` | готовые клипы стримера 16:9 для `/файт` |
| `СЫРЫЕ МАТЧИ/` | записи одной игры для `/матч` |
| `Clips Ready/` | **сюда за готовым**: папка `<Мем\|Файт\|Матч> <дата> <время нарезки> <название> [<длительность>]`, в ней ролики и после приёмки архив |

## Команды движка

```
python проверка.py                    что стоит, чего не хватает
python скачать.py "<ссылка>" --папка "../СТРИМЫ"   скачать (папка обязательна)
python раскладка.py "<стрим>" [--принять]   замерить, где вебка; сохранить для записи
python clipper.py batchname "<стрим>" --kind Мем   имя папки партии для --batch

python clipper.py scan "<стрим>"      громкость, кандидаты
python clipper.py asr  "<стрим>"      расшифровка речи
python clipper.py pick "<стрим>"      свести речь с движением -> candidates.json
python clipper.py cut  "<стрим>" ...  собрать клип
python clipper.py check "<клип>"      поискать чужую графику в кадре
```

Все флаги `cut` — в `движок/README.md`. Запускать из папки `движок`.

## Раскладки

| Стиль | Что в кадре | Когда брать |
|---|---|---|
| `game` | вебка сверху + игра снизу | игровые хайлайты |
| `life` | только вебка, вертикально | бытовое: разговоры, еда, гости |
| `cam` | вебка полосой 4:3 по центру | короткий ответ, реакция |
| `duo` | вебка крупно сверху + игра снизу | разговор на фоне игры |
| `talk` | вебка 70 % сверху + игра 30 % снизу | долгий монолог во время игры |
| `wide` | вебка узкой полосой сверху + игра на весь кадр | игровой момент, файт, клатч |
| `meme` | вебка сверху + бой из другого места снизу без звука (`--fill СЕК`) | **шаблон мемов**: любой разговорный момент |

Из записи стрима нарезаются только мемы. Игровые моменты в стримах не искать:
файты приходят готовыми клипами в `СЫРЫЕ КЛИПЫ/`, порядок описан в
`.claude/знания/11-сырые-клипы.md`.

Подробно — `.claude/знания/05-стили.md`.

## Первый запуск

Если файла `движок/мои_настройки.py` нет — это первый запуск.
`/начинаем` проведёт настройку: проверит окружение, спросит предпочтения
и создаст настройки. Повторно спрашивать не надо.

## Память между сессиями

`.claude/память/ПАМЯТЬ.md` — индекс, читается в начале каждой сессии.
Рядом по одному файлу на факт. Новый факт — команда `/запомнить`.

Память лежит внутри репозитория намеренно: её видно, её можно править
руками, и она не теряется при переустановке.

## Чего здесь нет и не будет

- Автозаливки в TikTok. Площадки это ловят и наказывают аккаунт;
  публикует человек руками.
- Накрутки просмотров, обхода модерации, скачивания чужих готовых нарезок.
- Готового ответа «какой момент зайдёт». Это решается смотрением кадров.
